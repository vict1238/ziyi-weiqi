# 联机对弈实现方案

当前桌面程序在本机运行 KataGo。“双方 · 自由复盘”允许同一台电脑控制黑白，尚未提供网络对战。人对人联机与远程调用 AI 是两个独立功能。

建议首版提供“创建房间 / 输入房间码”，采用以下结构：

`Windows 客户端 ⇄ HTTPS / WSS（443）⇄ 房间服务器 ⇄ 另一位玩家`

双方连接同一台服务器，房间码用于邀请，无需玩家设置端口转发。服务器需保持运行；分发新版 EXE 之外还需要部署服务。

## 对局流程

1. 创建房间，选择棋盘、规则、贴目、让子方向、数量及计时；另一位玩家输入房间码加入，双方确认后开局并锁定设置。
2. 客户端发送落子请求。服务器检查房间身份、执色、轮次、禁入、劫和局面版本，接受后向双方广播同一个确认结果。
3. 每条命令带唯一编号和预期版本，房间串行处理。重复提交、迟到消息、并发悔棋不能产生第二手或分叉。
4. 断线重连后凭独立的座位恢复凭证返回棋局，下载权威快照及完整历史。不能只恢复当前棋盘，因为全局同形判断依赖历史；客户端连接恢复也不等于座位与棋局已恢复。
5. 计时由服务器裁定，开局前约定断线宽限。悔棋需对方同意，认输只对自己的座位生效。连续停着后双方确认死子和结果；有争议时按规则恢复行棋。

房间码需过期与尝试次数限制，座位权限使用独立随机凭证。玩家不能凭房间码冒充另一方，也不能接收对方恢复凭证。服务端持久化对局和事件记录，进程重启后恢复房间。

## 与现有程序衔接

- 保留 .NET Framework 4.8 WinForms 界面，增加“本地人机 / 本地复盘 / 联机对弈”模式。
- 将独立的 `GoGame` 规则作为服务端校验的基础，补充正式对局的计时、身份及结算状态。客户端仅提交动作和显示已确认结果。
- 联机正式棋局中，导入棋谱、另开新局和复盘导航不能直接改掉服务器上的棋局。关闭自动应手、AI 落子、自弈和实时分析入口，赛后开放本地复盘；界面限制不能阻止用户运行外部 AI，因此不能承诺完善反作弊。
- 人对人服务器不需要 KataGo、模型或 GPU。远程 AI 另需 GPU 计算队列、访问配额、取消请求与成本控制。

## 技术选择

推荐单独部署 ASP.NET Core + SignalR 房间服务器，客户端加入 `Microsoft.AspNetCore.SignalR.Client`。官方包包含 .NET Framework 4.6.2 / .NET Standard 2.0 目标并支持 net48；项目需增加 NuGet 依赖管理及对应构建流程。参考：[官方包与兼容框架](https://www.nuget.org/packages/Microsoft.AspNetCore.SignalR.Client/)。

SignalR 负责连接与消息传输，并可配置自动重连；房间、座位、命令去重、历史恢复和权威计时仍需应用实现。参考：[微软 .NET 客户端和重连说明](https://learn.microsoft.com/en-us/aspnet/core/signalr/dotnet-client?view=aspnetcore-10.0)。

也可采用 Framework 自带的 `ClientWebSocket`，但要自行处理消息分片、心跳、串行发送、断线和重试。对当前房间对战需求，SignalR 可以减少这些底层工作。参考：[微软 WebSocket 与 SignalR 建议](https://learn.microsoft.com/en-us/aspnet/core/fundamentals/websockets?view=aspnetcore-10.0)。

首版范围可限定为好友房间、人对人、断线恢复、悔棋/认输和 SGF 导出；匹配、排行榜、观战与远程 AI 可随后独立增加。
